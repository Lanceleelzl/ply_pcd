## 2026-10-26 保存功能补齐

### 真实浏览器磁盘验收

- 使用独立 Chrome 自动化会话及真实 `FileSystemFileHandle.createWritable()`，将系统选路径窗口替换为 OPFS 文件句柄；保存控制、HTTP 请求与生产保存函数均使用现有实现。OPFS 是浏览器配置目录下的真实磁盘存储，此项不等于原生另存为弹窗或任意用户目录权限已通过。
- 四种成果的实际保存及回读通过：PLY 936 字节、Compressed PLY 884 字节、SOG 2640 字节、Streamed SOG ZIP 10724 字节，使用独立小型双 LOD 规则样本成果。另直接流式保存 `source/ply/point_cloud.ply`，256898154 字节，回读 SHA-256 为 `31cea51a90222c585091c0961796c2cfb7369b70e4f69a3e3c7d4891379cc104`，与本机独立读取源文件一致；此项验证保存链路，不代表该原始文件本轮重新完成编辑／转换验收。
- 五份文件均与本次响应 SHA-256 一致；刷新页面、重新获取磁盘文件句柄后，字节数和哈希仍完全一致。静态四份文件另与 Python 独立读取的 HTTP／源文件哈希核对。ZIP 每次实时打包的时间字段可能不同，必须与同一次响应比较，不能比较两次独立打包的整包哈希。
- 正常点击「下载整组 Streamed SOG ZIP」后，真实磁盘回读与对应响应一致，完成提示出现。注入未结束的响应后点击「取消保存」，页面显示取消且旧文件哈希不变。取消、长度不足和网络错误三个故障场景均通过真实磁盘写入流的 abort 保留旧文件；故障由测试注入，不是实际断网或磁盘写满。
