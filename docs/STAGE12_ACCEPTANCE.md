# 阶段 12 验收记录

## 结论

阶段 12「可确认的自动粗配准」已完成技术验收。4PCS 只生成可预览候选，用户采用后才进入现有 ICP 初值；失败、取消、低证据和几何歧义不会伪装为可靠结果。用户已于 2026-09-14 确认验收，相关改动已合并并推送到 `main`。

## 自动回归

- Windows CTest 使用 80 点非对称合成点云验证 `120°` 旋转及 `(25，−18，9) m` 位移恢复；固定种子逐元素可复现，双向覆盖率大于 99%，多参数结果去重为一个候选。
- 风险判定独立覆盖验证点不足与最佳／次佳分数相差不超过 5% 的场景，分别输出 `low_confidence` 与 `ambiguous`。
- 候选旋转去重使用 `R_leftᵀ × R_right` 的相对旋转角，避免将两个相同的非单位旋转误判为不同姿态。
- Web 回归覆盖候选只有预览／采用时改变姿态、失败时姿态不变、放弃时恢复原姿态并使既有结果失效，以及 `manual`／`4pcs`／`4pcs_adjusted` 来源传递。

## Windows 与真实数据

- 80 点合成会话在真实页面得到 1 个评分 1.000、双向覆盖率 100% 的候选；预览恢复 `B→A` 的 `−30°` 与平移。采用后修改 X 并执行 ICP，Job 与历史档案均记录 `initial_source=4pcs_adjusted`，最终 RMS 显示为 0.000000 m，浏览器控制台 0 错误。
- 真实 `source/ply/point_cloud.ply` 与 `source/pcd/GlobalMap.pcd` 使用默认 `delta=0.01 m` 时没有候选，安全返回失败。将 `delta` 调为 `0.1 m` 后生成 4 个候选，但最佳双向覆盖率仅 1.8%／1.7%，风险为 `ambiguous`；`delta=0.25 m` 的最佳覆盖率为 13.5%／11.9%，风险为 `low_confidence`。两组结果均不足以替代手动粗配准。
- 15% 重叠合成数据与高度对称的 `3×3×3` 点阵均未产生候选，Worker 明确失败，没有输出高置信度矩阵；失败路径保持用户原姿态。

## Docker 与运行上限

- `desktop-linux` 使用 Docker Engine 29.2.0 构建镜像 `ply-pcd-registration:stage12-acceptance` 成功；镜像内合成候选恢复成功，低重叠输入明确失败。
- 最大允许的 4 个 overlap × 4 个随机种子共 16 组搜索，Windows 用时约 0.63 秒，Docker Linux 用时约 1.37 秒；两端均去重为 1 个候选，风险为 `none`，评分约 0.999993。
- 服务端继续限制 overlap、随机种子、采样点数、基础搜索次数、候选数以及最多 16 组组合；粗配准任务复用现有队列、并发信号量、超时、取消、鉴权、归属隔离和生命周期清理。

## 已知边界

- 当前真实 PLY／PCD 基准数据的共同覆盖与几何证据不足，4PCS 不能给出可靠候选；产品按设计回退到手动粗配准。
- 验收时发现的 ASCII PLY CRLF 头兼容问题已在后续解析器任务中修复，并由独立回归覆盖；该问题不再是阶段 12 使用边界。
