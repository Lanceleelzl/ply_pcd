# 高斯编辑操作流程与核对记录

核对日期：2026-10-28。依据 `CLAUDE.md`、`GAUSSIAN_EDITOR_PLAN.md`、当前前后端实现及专项验收记录。本轮约定功能开发已补齐，可以开始用户功能验证；步骤与预期结果见 `GAUSSIAN_EDITOR_USER_VALIDATION.md`。此文说明操作逻辑和边界，不将未具备环境的测试标记为通过。

## 推荐操作顺序

1. 在「新建任务」选择单文件、LOD 文件组或完整数据集 ZIP／目录。LOD 组上传前检查文件列表：LOD 0 最精细，依次变粗，用「上移／下移」调整。坐标说明只附加到对应的本模块压缩 PLY／SOG 成果，不能混用其他文件的说明。
2. 进入工作台后，先在「层级／抽稀」选择工作 LOD。大模型使用粗层或抽稀工作层交互；点云预览的抽样数量不等于完整模型数量。抽稀工作层只用于交互，正式批处理仍读取选定原始层。
3. 在「边界」绘制平面、球体或旋转盒。平面边界沿全高生效，多个保留区域取并集，再扣除所有剔除区域。草稿检查完成后点击保存；尚未保存的草稿不会进入正式成果。
4. 需要改变输出几何时使用「模型变换」并保存；只想观察内部时使用「剖切」。剖切仅影响显示，不修改文件。地理位置在「坐标」中设置并保存，未知 EPSG／轴向／高度基准需要用户核实。
5. 回到「层级／抽稀」勾选正式处理层。缺少完整坐标头的 LOD 组，核对属于同一模型后确认同一局部坐标框架。页面有未保存边界、坐标或变换时，先保存或恢复设置，再点击「处理选中层级」。
6. 在「成果」按版本序号和时间下载 PLY，或生成 Compressed PLY／SOG。连续且点数递减的成果层级可生成整组 Streamed SOG。需要重新定位的压缩单文件同时保存对应坐标说明。
7. 希望回到某次成果的设置时，选择成果版本后点击「恢复该版编辑设置」。它新增一步编辑历史，可以撤销；旧成果文件继续保留，不自动重新计算。继续编辑成果文件本身时，将该成果重新导入为新任务。

## 各条工作逻辑

| 流程 | 当前约定和核对结果 |
| --- | --- |
| 上传和 LOD 顺序 | 服务端按列表顺序分配层级；本轮增加可见列表和排序，实际上传后核对 LOD 0／1 为 23／12 点 |
| 原始层和工作层 | 浏览器加载当前工作层，轻量预览／抽稀不覆盖原件；正式处理从选定原始 LOD 读取 |
| 边界与变换 | 规则使用共同场景坐标，按高斯中心判定；冻结已保存状态后逐层执行，草稿不混入成果 |
| 显示剖切 | 与正式裁剪分离；可保存显示设置和撤销，不能作为已经删减文件的证据 |
| 坐标 | 地理锚点和几何变换分别保存；已有坐标组合专项证据，高程基准不自动转换 |
| 历史与成果版本 | 编辑历史恢复参数，成果版本保留文件和冻结快照；本轮补齐快照恢复入口，旧版本无快照时明确拒绝猜测历史索引 |
| 加载和错误 | 首次加载有状态；首次读取失败显示原因及重试按钮，不伪装成新建任务页；任务切换清空旧取点和边界草稿 |
| 导出与下载 | 转换完成后才提供下载；流式保存支持取消、字节数、可信长度校验及失败中止，关闭成功后才提示完成 |
| 耗时操作 | 预读、抽稀、处理、导出有阶段与持久状态；只在有真实分母时显示百分比 |

## 本轮补齐及验证

- 增加 LOD 文件排序及文件／路径同步调整；真实创建测试任务 `bf9157a5-863f-45c8-87ed-c0c50cf80a25`，输入次序为 23／12 点，无旧任务顶点草稿继承。
- 未保存模型变换时，处理入口被阻止，成果数量与处理版本未变化；坐标草稿阻止处理的提示也已在浏览器复现。
- 从已有成果快照恢复规则成功，四份旧成果保持不变，撤销恢复有效；不通过历史索引推测成果设置。
- 等比缩放保存后同步三个轴的草稿值，并清除旧取点／查询结果，避免已保存仍显示未保存。
- 修复只读提示层遮住保存按钮并截获点击；提示仍显示，鼠标事件不再被其接收。
- 注入一次 HTTP 503 验证首次加载失败页面；恢复接口后点击重试进入工作台。此项是可控故障注入，浏览器日志中的该 503 是预期错误。
- 前端专项 33 项、服务规则／存储／说明专项 24 项、类型检查、生产构建及差异检查通过。浏览器使用独立验收服务，不覆盖用户任务。

## 未验证、排除与使用边界

| 项目 | 当前结论 |
| --- | --- |
| 系统「另存为」到桌面目录 | 已创建桌面验收目录并触发保存；Windows 操作工具因无法可靠识别 Chrome URL 停止，未确认文件保存。仍待实际操作核对，不能用 OPFS 通过替代 |
| 实际磁盘写满 | 用户已明确排除该项测试；保留写入失败处理，不制造磁盘不足 |
| 其他硬件、长期连续切层 | 本机已补测 80 次小层加载、8 次重进与大层交替释放，GPU 计数稳定；GC 增长已定位为 WebXR 全局监听，2026-10-28 修复后开发版和生产版十次重进的画布／数据缓冲区数量不再增加。其他硬件缺少设备，不保证全部硬件持续流畅 |
| WebGPU、SPZ 导出、LCC 原格式导出 | 不属于本轮已承诺的交付路径；现行渲染验收为 WebGL2，LCC／LCC2 作为输入 |
| 紧贴 GPU 裁剪边界 | 预览存在单精度误差带，正式成果使用服务端判定；界面已提示 |

当前没有将上述环境限制或排除项视为新的功能开发任务；模块仍不宣称所有设备、所有原生保存路径均已整体验收。
